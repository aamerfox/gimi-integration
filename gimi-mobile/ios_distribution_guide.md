# Guide: Generating & Distributing iOS App for Client Testing

Since the mobile app (`gimi-mobile`) is built using **Expo**, you have three main paths to generate and share iOS builds with clients before the official App Store release.

---

## Option 1: TestFlight (Recommended & Professional)
This is the official Apple-recommended way. It builds a production-ready `.ipa` file and uploads it to Apple App Store Connect. Clients install the app using the free Apple **TestFlight** app.

### Requirements:
*   An **Apple Developer Account** ($99/year).
*   An **Expo Developer Account** (Free tier is sufficient).

### Steps:
1.  **Install EAS CLI** (Expo Application Services):
    ```bash
    npm install -g eas-cli
    ```
2.  **Log in to Expo**:
    ```bash
    eas login
    ```
3.  **Configure EAS Build** (if not done yet):
    Run this command in the `gimi-mobile` directory:
    ```bash
    eas build:configure
    ```
    *Select `yes` to configure for iOS.*
4.  **Configure iOS Bundle Identifier**:
    Ensure your `app.json` contains a bundle identifier under `ios` (e.g. `com.traceplus.fleet`):
    ```json
    "ios": {
      "supportsTablet": true,
      "bundleIdentifier": "com.traceplus.fleet"
    }
    ```
5.  **Build and Upload to TestFlight**:
    Run the EAS build command. It automatically handles Apple certificates and registers the app in App Store Connect:
    ```bash
    eas build --platform ios --profile production
    ```
    *Follow the prompts to log in to your Apple Developer account.*
6.  **Add Clients as Testers**:
    - Log in to [App Store Connect](https://appstoreconnect.apple.com).
    - Go to **My Apps** > **trace+** > **TestFlight**.
    - Under **External Groups**, create a group (e.g., "Client Testers") and add the clients' email addresses.
    - They will receive an email invitation to download TestFlight and install the app.

---

## Option 2: Ad Hoc Internal Distribution (Via Shareable Link)
This method allows clients to download the app directly from a web link (e.g., diawi.com or expo.dev) without going through TestFlight or App Store beta reviews.

### Requirements:
*   An **Apple Developer Account**.
*   The **UDID (Unique Device Identifier)** of each client's iOS device.

### Steps:
1.  **Collect UDIDs**:
    - Ask clients to visit a site like [get.udid.io](https://get.udid.io) on their iPhones to find and copy their device UDID.
2.  **Register UDIDs and Devices**:
    - Run this command in the project directory:
      ```bash
      eas device:create
      ```
    - Follow the prompts to log in to Apple and register the UDIDs.
3.  **Build the Preview Profile**:
    - Update `eas.json` to configure the `preview` profile for ad-hoc distribution:
      ```json
      "preview": {
        "distribution": "internal"
      }
      ```
    - Run the build command:
      ```bash
      eas build --platform ios --profile preview
      ```
4.  **Share the Installation Link**:
    - Once the EAS build completes, Expo will output a shareable URL (e.g., `https://expo.dev/artifacts/...`).
    - Send this link to the clients. They can open it on their registered iPhones and click **Install** to download the app directly.

---

## Option 3: Expo Go (Development Preview)
For immediate, rapid previews of your layout and changes without building binaries or requiring Apple Developer credentials.

### Requirements:
*   None (No Apple Account needed).

### Steps:
1.  **Publish a Development Update**:
    Ensure you have `expo-updates` installed, then run:
    ```bash
    npx expo export
    ```
    *(Or configure EAS Updates to host it on Expo's servers).*
2.  **Invite Clients via Expo Go**:
    - Ask the clients to install the free **Expo Go** app from the App Store.
    - Share the project URL generated by `npx expo start --go` or the Expo dashboard deployment page.
    - Scanning the QR code inside Expo Go will open and run the app.

*Note: Expo Go does not support custom native native plugins or modules (like specialized background trackers if they require custom native code outside the Expo SDK). If you have custom native modules, you must use Option 1 or Option 2.*
